sloop is a single binary with nothing beside it: no runtime to install first, no service to register, no account. It builds for Windows, Linux and macOS on both x86-64 and aarch64, and the installer picks the right one by asking the machine rather than asking you.

What it just did

@if (os() === 'windows') {

It worked out that this machine is {{ target() }}, downloaded {{ archive() }} and SHA256SUMS from the same release, checked the first against the second before unpacking a byte of it, and put sloop.exe in %LOCALAPPDATA%\Programs\sloop\bin.

Then it added that directory to your PATH — in HKCU\Environment, which is your own user's environment and needs no elevation. The entry is written as %LOCALAPPDATA%\Programs\sloop\bin rather than expanded, so it survives a renamed account or a restored image, and the installer broadcasts WM_SETTINGCHANGE so terminals opened afterwards pick it up without a sign-out. Running the installer twice leaves one entry, not two.

bash on macOS is the one that catches people out. Terminal starts a login shell, and a login bash reads the first of those three files and no other — so writing ~/.bashrc would be writing to a file nothing opens. Creating a ~/.bash_profile on a machine that keeps its settings in ~/.profile would silently stop bash reading ~/.profile at all, so an existing file always wins and a new one is created only when there is nothing.

}

The block is fenced between # >>> sloop >>> and # <<< sloop <<<, and the path inside it is written with $HOME rather than expanded. The markers are what makes removing it later an exact operation rather than a person editing a file by hand. Running the installer twice leaves one block, not two.

}

Or take the archive by hand

Every release carries six archives and a single SHA256SUMS over all of them, in sha256sum -c format so you can check one without trusting a script to do it. No version appears in an asset name, which is what makes /releases/latest/download/<asset> resolve to the newest release with no API call and no token.

SmartScreen, if you downloaded it with a browser

sloop's binaries are not code-signed, so a file fetched with a browser carries the Mark of the Web and SmartScreen will warn about it. Either use More info → Run anyway, or take the mark off:

The one-liner at the top of this page is unaffected, and so is irm on its own: neither sets the Mark of the Web, so there is nothing to warn about. This applies only to a manual download through a browser.

Or build it with cargo

The crate is dbsloop and the command is sloop — sloop on crates.io belongs to an abandoned 2019 project, and Cargo lets a binary be named independently of the package that ships it.

That puts the binary in ~/.cargo/bin, which cargo's own installer already put on your PATH — so none of the PATH handling above applies. To build the working tree instead:

git clone https://github.com/DBSloop/sloop then cd sloop/cli && cargo install --path .

Removing it

sloop uninstall is the one to run first, while the binary still works. It knows what sloop built on this machine — a PostgreSQL it downloaded, its own database, the role that owns it, the registry — and it removes all of that, then the binary and the PATH entry, at the end. A script cannot do that, because a script cannot know which PostgreSQL was sloop's.

The script below is the fallback, for a machine where the binary is gone, or broken, or was never on PATH. It removes the binary and the PATH entry and nothing else — so it is not a shorter way of doing the command above, it is what is left when that command cannot run. If sloop's own state is still there and the binary could still remove it, the script stops and names the flag rather than deciding for you.

@if (os() === 'windows') { -BinaryOnly } @else { --binary-only } says take the binary and the PATH entry and leave sloop's database, registry and config alone — for replacing sloop rather than removing it. Reset and uninstall covers what each of them destroys and what it leaves.

Backups are never deleted. Not by the uninstall script, not by sloop uninstall, not by sloop reset, not ever. A registry is a minute of typing and a PostgreSQL is a download; a dump that is gone is gone.
