Why --yes, --force and --confirm are three things

They look interchangeable and are not, and reaching for the wrong one is how an automated run either stops when it should not have or destroys something it should not have.

  • --yes answers a question. A command that would stop and ask something proceeds. It is never enough to destroy a named thing, and it is never a way past a refusal.
  • --force overrides a refusal. A refusal is sloop declining to do something because of what it found — a circular foreign key, a source that is also the destination. It answers no questions, and the refusal that can be overridden says so when it fires.
  • --confirm <NAME> types the name out. It is the only way to run a destructive command with no terminal, and it has to match exactly — so a scheduled line names the thing it destroys and cannot be repointed at something else by editing one flag.

With no terminal to ask at, sloop never prompts. It exits 2 and names the exact flag that would have answered the question, which is why a scheduled run can fail but cannot hang. Automation has the exit codes and the rest of it.
