Supported today — PostgreSQL · MySQL · MariaDB

Back up. Restore. Mirror. Sync.

sloop registers a database once — a name, a host, a role — and then runs every operation against that name, from a menu or from a flag, on Windows, Linux and macOS. One binary, no daemon, no account.

Your credentials never leave your machine. No telemetry, no analytics, no update pings — and nothing in the binary that could phone home.

01

Not a policy. A property of the build.

Plenty of tools promise not to send your data anywhere. This one cannot. There is no HTTP client anywhere in the dependency graph — no reqwest, no hyper, no ureq — so there is nothing in the binary that knows how to open a socket to the internet. Continuous integration fails the build if one ever appears.

The one job that genuinely needs the network — fetching a client tool that Windows does not ship with — shells out to the system's own curl after you say yes. The claim survives inspection because it is checkable, and this is how you check it in thirty seconds.

Nothing is written to a log that could not be pasted into a public issue. No password reaches a config file, a dump filename, or ps.

02

Four verbs, and one of them deletes things.

mirror and sync are different commands with different engines, and the difference is worth reading before you run either. mirror leaves the destination identical to the source, so anything the source does not have is gone. sync merges, and keeps what the destination already had.

  • sloop backup

    Dump it, and write down what you dumped.

    Every backup lands in its own UTC-stamped directory with a manifest beside it: engine version, size, SHA-256, duration, per-table row counts, and both timestamps with the offset. backup --all runs to the end and then tells you which databases failed, rather than stopping at the first one.

  • sloop restore

    Put it back, having said which one out loud.

    Restoring over a database means typing its name, not clicking yes. The destructive half of this tool is typed, every time, and there is no flag that turns that into a keypress.

  • sloop mirror

    An exact copy. The destination ends up identical.

    Dump and restore. Anything in the destination that is not in the source is gone afterwards — that is what exact means, and it is the whole difference from sync. The source is only ever read; no statement written against it changes anything, not even ANALYZE.

  • sloop sync

    A merge. Destination-only rows are kept.

    Rows added, existing rows replaced, and anything the destination had that the source does not is left alone. COPY into temp tables, then upsert in foreign-key order. It needs a primary key on every table, resets sequences and identity columns afterwards, tells you which source-deleted rows will linger, and refuses outright on circular foreign keys.

03

Register it once. Then just use the name.

A registry lives in your project, the way .git does — sloop walks up from wherever you are standing and uses the nearest one. There is a global registry too, for the databases that are not a project's. A name that exists in both resolves to the project's; --global forces the other, and global:name says so outright.

Verification is exact rather than estimated: every row is counted on both sides. The planner's estimate has been seen reporting double the true number, so it is available as a deliberate fast path and is always labelled an estimate — never presented as proof.

Directory names are UTC so they sort correctly and survive daylight saving. Every line a person reads is in local time, with the offset, and the manifest records both.

04

Four ways to hold a password. None of them is a file.

No plaintext password is written anywhere — not to a config file, not to a log, not into a dump's filename, and not into ps output. Which route you get depends on the machine you are on.

  • By default

    The OS keyring

    Credential Manager on Windows, Keychain on macOS, Secret Service on Linux.

  • Headless Linux

    An encrypted file

    XChaCha20-Poly1305 with an Argon2id-derived key, for a box with no desktop session.

  • Automation

    An environment variable

    ${DB_PASSWORD} is interpolated at read time, so the registry holds the name and never the value.

  • Teams

    A password command

    --password-command reads it from your password manager. It arrives down a pipe, so it never reaches ps.

Encrypted backups

The asymmetry is the point.

Backups are encrypted to an age public key that sits in the config, so a scheduled backup at three in the morning needs no secret to unlock. The private key lives in the keyring, and only a restore ever asks for it.

The first encrypted backup refuses to run until that key has been exported somewhere else, or you have explicitly said you do not want to. Losing it loses everything, and that is said once, hard, at the only moment it can still be acted on.

05

Written to be run by a scheduler at 3am.

It never asks a question it cannot ask. When standard input is not a terminal and something needs confirming, it exits with an error naming the exact flag that answers it — because a scheduled run that hangs waiting for a keystroke is the worst failure this tool could have.

One lockfile per database, so an overrunning backup cannot race the next scheduled run. Every interactive session ends by printing the flag equivalent of what you just did, so a thing you worked out by hand becomes a line you can paste into a crontab.
